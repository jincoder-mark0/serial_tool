# S-059 — 앱 종료 시 RX 데이터 로거가 정리되지 않음

- Status: TODO
- Recommended model: **하위(Sonnet) 가능**
- 선행: S-055 (발견 경위)
- Skills to load: task-done

## 목적 (Why) — S-055 수행 중 발견, 상위가 재확인 (2026-08-22)

`core/data_logger.py`의 `DataLoggerManager.stop_all()`이 **저장소 어디에서도 호출되지 않는다**
(전수 확인: `presenter/`·`main.py`·`view/`에서 호출처 0건). `stop_logging(port)`는 사용자가
로깅 토글을 **끌 때만** 불린다.

**결과**: RX 데이터 로깅을 켠 채로 앱을 종료하면
- 종료 시퀀스(`MainPresenter.on_close_requested`)가 로거를 닫지 않고,
- DataLogger의 쓰기 스레드는 데몬이라 프로세스 종료와 함께 강제로 죽는다 →
- **큐에 남아 있던 데이터가 유실되고 파일이 정상적으로 닫히지 않는다**(PCAP은 특히 손상 위험).

**S-045에서 `stop_logging()`의 드레인 유실을 고쳤지만, 종료 경로에서 호출되지 않으므로 그
수정이 발동하지 않는다.** 고친 안전장치가 실제로는 안 불리고 있었다.

대조: 시스템 로그 라이터는 S-055에서 `on_close_requested`에 닫기를 배선했다.

## Steps

1. 종료 지점을 확인한다 — `presenter/main_presenter.py`의 `on_close_requested`가 실제 종료
   시퀀스다(`lifecycle_manager`에는 종료 시퀀스가 없음을 S-055가 확인).
2. 종료 시 `data_logger_manager.stop_all()`을 호출하도록 배선한다.
   - **순서 주의**: 워커(포트)를 먼저 정리하면 그 사이 들어온 데이터가 로거에 안 갈 수 있고,
     로거를 먼저 닫으면 남은 RX가 기록되지 않는다. 현재 종료 시퀀스를 읽고
     **"연결 종료 → 로거 정리"** 순서가 맞는지 판단해 근거를 보고하라.
   - `stop_all()`이 여러 포트를 순회하며 실패해도 나머지를 계속 닫는지 확인한다
     (한 포트 실패로 다른 포트 파일이 안 닫히면 안 된다).
3. **테스트**: 로깅을 켠 상태에서 종료 시퀀스를 호출하면 로거가 닫히고 파일이 완성되는지.
   S-045가 만든 `tests/test_data_logger.py`의 패턴을 재사용하되, **종료 경로를 타는 통합
   테스트**여야 한다(단위로 `stop_all`만 부르면 이 결함을 못 잡는다).
4. 같은 유형이 더 있는지 확인: 종료 시 정리가 필요한데 배선되지 않은 자원
   (열린 파일·스레드·타이머). 발견하면 보고하고, 범위가 크면 목록만 남긴다.

## 검증 방법

전체 pytest(offscreen, 기준선은 직전 커밋 값) + 실제 파일 산출물 확인(로깅 켠 채 종료 →
파일이 유효한지, PCAP이면 헤더·패킷 구조가 온전한지 — S-045의 바이트 검증 재사용) + ruff.

- [ ] 정리 순서 판단 근거 보고, 일부 실패가 나머지를 막지 않음.
