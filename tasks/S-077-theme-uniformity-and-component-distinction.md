## 목적 (Why)

**① 컴포넌트 구분** — "버튼과 리스트 박스 같은 서로 다른 컴포넌트의 구분이 잘 안 되는
것 같다. 색이 똑같아서 그런가?" 짐작이 맞았다.

| 테마 | 버튼bg↔입력bg | 버튼테두리↔입력테두리 |
|---|---|---|
| dark | 1.47 | 1.29 |
| light | 1.32 | **1.00 (완전 동일)** |
| classic | 1.54 | **1.00 (완전 동일)** |
| dracula | 1.73 | 1.94 |

게다가 `QComboBox`가 테마마다 편이 달랐다 — dark·dracula는 버튼 배경, light·classic은
입력 배경. "콤보는 누르는 것인가 입력하는 것인가"에 테마마다 다른 답을 하고 있었다.

**② 파일 통일성** — "모든 테마 파일이 통일성이 있어야 관리가 수월하다. 클래식은 모양
때문에 어쩔 수 없지만 최대한 통일성이 있어야 한다."

S-073에서 클래식에만 override 블록 13줄을 **덧붙여** 79규칙 구조가 92규칙(고유 82)으로
어긋나 있었다. dark·light·dracula는 79규칙·순서까지 완전히 같았는데 클래식만 튀었다.

## 수행 결과

### 구조 통일 — 4테마 80규칙, 셀렉터 집합·순서 완전 일치

- 클래식의 덧붙인 블록을 제거하고 **기존 규칙 안으로 접어 넣었다.**
- 모든 테마가 `border-radius`를 **명시**한다(클래식만 0, 나머지는 common과 같은 값).
  값이 테마 파일에 드러나야 "왜 여기만 각진가"를 파일 안에서 알 수 있다.
- 테마 어휘에 없던 `QToolBar QToolButton` 기본 규칙을 4테마 모두에 추가했다.
  한 테마에만 규칙이 있으면 다른 테마에서 그 위젯이 공용 스타일로 떨어진다.

### 콤보를 입력 계열로 통일

값을 고르는 것이지 동작을 실행하는 것이 아니므로 입력에 가깝다고 판단했다.
dark `#1e1e1e` / dracula `#21222c`로 바꿨고 light·classic은 이미 입력 배경이었다.

### 버튼 테두리로 두 부류를 가른다

배경 대비만으로는 부족했으므로(1.32~1.73) 테두리를 분리했다. **기존 색에서 최소로
이동**하는 값을 탐색해 팔레트를 지켰다 — 대비 최대화만 노리면 순백/순흑으로 수렴해
테두리가 과하게 굵어 보인다.

| 테마 | 변경 | 입력 테두리 대비 |
|---|---|---|
| dark | `#505050` → `#5f5f5f` | 1.62 |
| light | `#c0c0c0` → `#979797` | 1.61 |
| classic | `#707070` → `#515151` | 1.60 |
| dracula | 유지 (`#6272a4`) | 1.94 (이미 충족) |

dracula는 이미 구분되고 유채색 테두리가 팔레트의 일부라 건드리지 않았다.

## 테스트

`tests/test_theme_structure_uniformity.py` — 값이 아니라 **관계**를 고정한다.
팔레트는 테마마다 다르므로 절대 색을 박으면 테마를 손볼 때마다 깨진다.

1. 4테마 셀렉터 집합 동일
2. 4테마 규칙 등장 순서 동일
3. 버튼 테두리와 입력 테두리가 구분(≥1.5)
4. 콤보가 입력 계열

light의 버튼 테두리를 옛 값으로 되돌려 1건, dracula에 규칙 하나를 덧붙여 2건이
실패하는 것을 각각 확인했다.

`tests/test_classic_square_corners.py`의 셀렉터 비교도 손봤다. 쉼표로 묶인 목록을
개별 셀렉터로 펴서 비교한다 — `common.qss`는 스크롤바 핸들을 세로/가로로 나눠 쓰고
테마 파일들은 하나로 묶어 써서, 문자열 그대로 비교하면 같은 것을 다르다고 판정했다.
