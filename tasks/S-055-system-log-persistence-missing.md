# S-055 — 시스템 로그 저장이 실제로 동작하지 않음

- Status: TODO

- Skills to load: task-done

## 목적 (Why) — S-052 수행 중 발견 (2026-08-22)

시스템 로그 위젯의 "저장(로깅)" 토글 버튼은 **어디에도 연결되어 있지 않았다**.
S-052 이전 시그널 `sys_logging_started(str)`의 **구독자가 저장소 전체에 0건**이었다.

즉 사용자가 시스템 로그 저장을 켜면:
- 파일 다이얼로그가 뜨고(S-052 이전에는 위젯이 직접 띄웠다),
- REC 표시가 켜지지만,
- **파일에는 아무것도 기록되지 않는다.**

S-052는 제어 흐름(누가 다이얼로그를 열고 상태를 바꾸는가)만 통일했고, 실제 영속화 배선은
요청 범위 밖이라 손대지 않고 코드 주석과 보고로 남겼다 — 올바른 범위 판단이었다.

대조: RX 데이터 로그(`DataLogWidget`)는 `data_logger_manager`를 통해 실제로 기록된다.

## 결정할 것 (상위)

1. **시스템 로그 파일 저장이 필요한 기능인가?**
   - 필요하다면: RX 로그와 같은 방식(`core/data_logger.py`)을 쓸지, 시스템 로그는 텍스트만
     남기면 되므로 단순 파일 쓰기로 충분한지. 포맷(BIN/HEX/PCAP)은 시스템 로그에 무의미하므로
     **텍스트 전용**이 자연스럽다.
   - 불필요하다면: **토글 버튼과 관련 UI를 제거**한다. 눌러도 아무 일이 없는 버튼을 두는 것이
     더 나쁘다(사용자를 속인다).
2. 필요하다면 저장 대상: 화면에 보이는 라인 그대로인지, 필터 적용 전 원본인지.

## Steps (결정 후)

- **저장 구현을 택한 경우**: Presenter의 `_on_sys_logging_start_requested`가 실제 파일
  기록을 시작하도록 배선. 기록 주체는 Model/Core 계층에 두고(View·Presenter가 직접 파일을
  쓰지 않는다), 종료·앱 종료 시 파일이 정상 닫히는 경로를 확인한다(S-045의 DataLogger
  종료 유실 수정과 같은 원칙 — 조용히 버리지 않는다).
- **제거를 택한 경우**: 토글 버튼·시그널·Presenter 핸들러·언어 키를 함께 제거하고,
  `get_state`/`apply_state`에 관련 키가 있으면 마이그레이션으로 정리.
